analysis_capabilities#

Which analysis goals a cipher can express, which operators block the rest, and what a run returns.

capabilities.analysis_capabilities.resolve_goal(goal)[source]#

The goal actually modelled for goal: itself, or the middle-round goal it is built on.

capabilities.analysis_capabilities.required_version(operator_class, goal)[source]#

The model-version suffix goal requires for operator_class.

Applies GOAL_MODEL_VERSION_RULES as set_model_versions does: in order, each matching rule overriding the previous. Raises when no rule covers the operator, which means the goal is missing its scope=None fallback.

capabilities.analysis_capabilities.operator_support(operator_class, goal, model_type)[source]#

Whether operator_class declares the version goal needs: one of the three states above.

capabilities.analysis_capabilities.model_scope_constraints(cipher, config_model=None)[source]#

Exactly the operators gen_round_model_constraint_obj_fun would generate a model for.

Mirrors the generation loop, honouring positions and the gen_input_model / gen_output_model switches; set_model_versions sweeps wider on purpose. A list, not a generator: callers make one full pass, and a generator would go empty on a second.

capabilities.analysis_capabilities.scope_operator_classes(cipher, config_model=None)[source]#

{class name: class} for every distinct operator inside the query scope.

capabilities.analysis_capabilities.goal_report(cipher, goal, model_type, config_model=None, scope_classes=None)[source]#

A structured answer for one (goal, model_type) pair; capability_report gives all of them.

Keys: feasible (nothing in scope declares it cannot), verified (and every operator declares the required version – about declarations, not an end-to-end check), blockers and unverified as sorted (class, suffix) lists, plus goal, modelled_as, model_type and operators. Read-only: assigns no model_version.

modelled_as differs from goal for the 4 impossible-differential and zero-correlation goals: the answer is about the middle-round goal they are built on, which is the only thing the operators declare anything about.

capabilities.analysis_capabilities.capability_report(cipher, model_type, config_model=None)[source]#

{goal: goal_report(...)} for every goal, walking the cipher’s operators only once.

capabilities.analysis_capabilities.feasible_goals(cipher, model_type='milp', config_model=None, require_verified=True)[source]#

The goals cipher can express under model_type, in ALL_GOALS order.

require_verified=True (the default) keeps only goals every operator declares. False also accepts goals held up solely by operators that declare nothing, which are not known to work: the late version ... not existing error is what such an operator produces.

capabilities.analysis_capabilities.explain_goal(cipher, goal, model_type, config_model=None)[source]#

goal_report rendered for a human or an error message; "" when nothing is wrong.

capabilities.analysis_capabilities.goal_support_matrix()[source]#

{goal: {model_type: {state: sorted class names}}} over every concrete operator class.

Cipher-independent: what any cipher could express, not what this one can. All three states are reported, so an operator that declares nothing stays under UNVERIFIED.

capabilities.analysis_capabilities.trace_classes()[source]#

{class name: {...}} for every AttackTrace class, merged along the real MRO.

Per entry: bases; data_keys, every key an instance carries; read_keys, the subset the class bodies read back; constructed_keys, the subset its writer sets; unresolved_constructed, writer keys that are variables and so not statically known; and exports as {format: implemented | unimplemented | abstract}. All read out of the source, so none of it can disagree with the code.

capabilities.analysis_capabilities.export_formats(class_name=None)[source]#

{format: state} for one trace class, or the union over the concrete ones.

unimplemented is a method that exists and raises NotImplementedError: having a save_tex is not being able to export LaTeX. mixed would mean two concrete classes disagree, which none do today.

capabilities.analysis_capabilities.recheck_available()[source]#

What reference/ offers for independently re-checking a result.

reference is an optional dependency – published results, not part of the pipeline – so its absence is reported rather than raised. analyses comes from reference.CLAIMS: an analysis missing from that vocabulary cannot be recorded as a claim, let alone replayed.

capabilities.analysis_capabilities.recheck_parameters()[source]#

{check: {name: {required, default}}} – what a replay has to be given.

recheck_path says which checks apply and never what they need. Read from each check’s own signature, so the four turn out to take the same four arguments: the claim spec, an optional pre-built cipher, a model_type and a config_solver. The round count and the bound are not arguments – they come out of the claim, which is why a replay needs the claim file and not a configuration of its own.

capabilities.analysis_capabilities.recheck_path(entry_point)[source]#

(applicable checks, reason) for independently re-checking what entry_point returns.

Both the analysis and the shape matter. reference’s four checks replay a trail – pin it into the model, solve, compare – so a result that is not a trail cannot go through them whatever its analysis. A bare optimum still has a path: reference.compare_bound.

capabilities.analysis_capabilities.entry_point_parameters(entry_point)[source]#

{name: {required, default}} for what an entry point takes, from its own signature.

result_shapes said what comes back and never what goes in, so a consumer could read the goal and the objective-target vocabularies without learning which argument takes which – or that two_stage_trail_search is handed a factory and a round count where the other five take a built cipher. Same shape as the A axis reports a factory’s parameters, so the two read alike.

capabilities.analysis_capabilities.result_shapes()[source]#

{entry point: {...}} for the six entry points of attacks/attacks.py.

Per entry: parameters, what the call takes (see entry_point_parameters); returns (one of the three shape constants); element with the data_keys and exports that come with it, empty when the shape carries no AttackTrace; goals, the goals this entry point accepts; recheck_checks with recheck giving the reason when there are none; and empty_means, what an empty result does not tell you.

capabilities.analysis_capabilities.result_for_goal(goal)[source]#

What running goal gives back: its entry point’s result_shapes() entry.

The join the two halves of this module exist to make: feasible_goals says a goal can be expressed, this says what comes back and whether it can be re-checked. Several entry points can accept one goal – DIFFERENTIAL_GOALS reaches both diff_attacks and two_stage_trail_search – so the answer is a dict keyed by entry point.

capabilities.analysis_capabilities.describe_result(entry_point)[source]#

One result_shapes() entry, raising with the valid names if there is no such entry point.

capabilities.analysis_capabilities.call_vocabulary()[source]#

The other arguments an analysis takes, beside goal and model_type.

Re-exported from tools/model_configuration.py so a consumer reads one place instead of four. Listing the goals without these answered half the question: a goal is not callable until objective_target and the constraint markers are known, and AT MOST / EXACTLY / AT LEAST need a number appended where the bare keywords do not.

capabilities.analysis_capabilities.solver_backends()[source]#

Which solver backends are installed on this host, per model type.

Host state, not a repository fact: the same checkout answers differently elsewhere, so this never belongs in a cached manifest without the host it came from. A goal being feasible says the model can be built, not that anything here can solve it – a backend that cannot load raises rather than returning an empty result, which is deliberate.

TODO.md records the known limit: a backend whose module imports but whose native library fails to load is still reported available.

capabilities.analysis_capabilities.host_dependent_fields()[source]#

The parts of this module’s answers that come from the host rather than the repository.

capabilities.analysis_capabilities.shape_asymmetry()[source]#

The two things these signatures hide, which no other function here states outright.

recheck#

Replaying published cryptanalysis results through OCP.

The results themselves are not here. reference/ is the source-material store – the papers, the claims read out of them under reference/data/, and reference/EXTRACTION.md, which is the authority on the claim format. This package is only the machinery: it turns such a claim into OCP objects, pins it, and reports whether the model agrees.

The split is so that the two can be present independently – material without a checker, or a checker with no material – which capabilities.recheck_available() reports as separate facts.

OCP has no knowledge of this package; the dependency runs one way, and test/operators/test_module_boundaries.py keeps it that way.

recheck.build_cipher(spec, rounds=None)[source]#

Instantiate the primitive the claim is about.

A trail claim fixes the round count in target.kwargs. A bound claim states a value per round instead, so the count is passed in here and injected under target.rounds_kwarg ("r" unless the primitive names it otherwise).

recheck.assignments_to_solution(cipher, assignments)[source]#

[{function, round, layer, value, nwords?}] -> {var_id: 0/1}.

value is the whole state as "0x..."/"0b...", MSB first. nwords pins only the first n words, for a target narrower than the state the paper wrote the value against.

The word count and width come from the cipher, never from the claim file, so a claim cannot disagree with the primitive about how a state splits; a value wider than its target is rejected rather than truncated.

recheck.pin_constraints(solution, model_type='milp')[source]#

Constrain every variable the claim pins to the value it pins it to.

recheck.solution_to_assignments(cipher, solution, places)[source]#

[{function, round, layer, value}] for the states places names, read off a solution.

The inverse of assignments_to_solution, for writing a claim rather than replaying one. places is a list of (function, round, layer) because a solution covers every variable in the model while a claim records a chosen few – the 35 trail claims here hold between 6 and 34, typically each round’s input state plus the subkeys. Both directions read the state in state_var_ids order, so a claim written here replays unchanged.

Whole states only: assignments_to_solution takes an nwords to pin a prefix and places cannot say that, so a narrowed claim is not writable from this side. No claim in the corpus narrows for real – the six that carry nwords set it to the state’s own width – and a test holds that, since otherwise this would raise about a missing value instead.

recheck.check_bound(spec, model_type='milp', config_solver=None, rounds=None)[source]#

Search the optimum for each round the claim covers and test the stated relation.

A bound claim carries no trail: it says what the best value over r rounds is ("="), or at least is (">=", how design documents usually phrase a security argument), or at most is ("<=", a trail was found but optimality was not proven). Nothing is pinned, so every round is a full search – pass rounds to check only part of the table.

recheck.max_feasible_prefix(spec, cipher=None, model_type='milp', config_solver=None)[source]#

How many of the claim’s assignments can be pinned before the model turns infeasible.

Equal to the number of assignments when the whole claim is feasible; otherwise the index of the first one that cannot hold, which is where to look for the transcription error.

recheck.search_key(spec, rounds)[source]#

What a bound search actually depends on, so identical searches can be shared.

Several papers state the same optimum, and each is a separate claim file. The search behind them is one and the same: it is fixed by the primitive, the round count and the goal, and knows nothing of who claimed what. Batch runners key a cache on this.
